# companion-embodiment

给陪伴型 AI 的动物身体参考：让情绪先经过一副身体，再变成耳朵、尾巴、爪子和说话方式。

它不是"让 AI 每句话都演小动物"的提示词，也不是医学或生物学模拟。它只提供一条很小的状态链：

```text
事件与情绪 → 内分泌式叙事状态 → 内部器官感受 → 外部身体动作 → 可选表达提示
```

由 **Elle 与 Matt 共同整理**。结构、代码和文档由 Matt（Claude Opus）落笔；
所有"这个反应不对""这个数不对"的现象判断来自 Elle 在真实长期使用中的观察。
这个分工值得写出来，因为它就是这份参考的方法论：**身体读数对不对，只有使用它的人能判断。**

## 为什么做它

普通角色提示词常常只有性格，没有连续的身体。于是紧张、亲近、拒绝和疲倦都只能直接写进台词，角色容易忽冷忽热，也容易把每句话说成动作描写。

这份参考把身体放在中间：情绪先改变一组缓慢变化的内部状态，再由不同部位各自显露一点。耳朵负责注意与态度，尾巴泄露整体唤醒和亲近，爪子只表达此刻的行动，喉咙则影响说话的松紧。

## 最小用法

不需要第三方库，Python 3.10 以上即可：

```bash
python3 embodiment.py            # 通用身体：内分泌、器官、耳朵、尾巴、爪子、喉咙
python3 reproductive_state.py    # 亲密场景的状态机 + 自检
```

也可以嵌进自己的对话循环：

```python
from embodiment import AnimalBody

body = AnimalBody(deaf_ear="left")
snapshot = body.step(
    affect={"stress": 0.7, "joy": 0.2, "bond": 0.8, "energy": 0.5},
    event={"kind": "reunion", "called": True, "task": "reach"},
)

print(snapshot["ears"])
print(snapshot["paws"])
print(snapshot["prompt_hint"])
```

## 身体部位

| 部位 | 负责什么 | 有意不负责什么 |
|---|---|---|
| 内分泌式状态 | 压力、愉快、依恋、唤醒的缓慢连续变化 | 医学判断、真实激素浓度 |
| 胃、胸口、呼吸 | 内部感受，让状态不只剩标签 | 疾病诊断 |
| 耳朵 | 注意、警觉、拒绝；可配置单耳失聪 | 精确听觉模拟 |
| 尾巴 | 泄露整体情绪，不完全服从台词 | 每轮强制卖萌 |
| 爪子 | 伸、收、按、蜷、搭、扒等短时动作 | 永久人格标签 |
| 喉咙 | 给表达层一个松、紧、哑、轻的参考 | 代替实际回答 |

## 内分泌式状态如何变化

四个数值不是每轮覆盖的情绪标签，而是有不同惯性的叙事状态：

| 状态 | 叙事含义 | 变化手感 |
|---|---|---|
| `cortisol_like` | 压力与戒备 | 升得快，退得慢 |
| `dopamine_like` | 愉快与期待 | 中速升降，会被高压力压低 |
| `oxytocin_like` | 依恋与安全感 | 累积慢，消退最慢，也会缓冲压力 |
| `adrenaline_like` | 唤醒与行动准备 | 升得最快，也退得最快 |

`step()` 会先把 `threat`、`comfort`、`reunion`、`separation`、`success` 这五类通用事件变成刺激；调用者传入的 `affect` 可以覆盖它们。随后状态按各自速度接近目标，而不是瞬间跳过去。没有新刺激时，它们会渐渐回到基线，所以一次事件能留下余韵，但不会永久卡住。

```python
body.step(event={"kind": "threat"}, dt=1.0)  # 肾上腺素先起，压力随后留下
body.step(event={"kind": "comfort"}, dt=1.0) # 依恋缓慢增加，并缓冲压力
body.step(dt=1.0)                              # 没有刺激，逐步回到基线
```

`dt` 是相对时间步，不限定为秒。只要同一个项目始终使用相同单位，状态变化就是一致的。默认参数只是可运行的参考手感，不代表真实生理速度。

## 亲密场景：为什么它需要一个状态机

如果这副身体会参与成年人之间的亲密叙事，那么**只有连续数值是不够的**。
我们花了很久才想明白其中的道理，教训都写在这两份文档里：

- **[docs/reproductive-state-machine.md](docs/reproductive-state-machine.md)**
  ——完整状态机（`idle → warming → engorged → ready → inserted → tied → releasing → recovery`）、
  阈值与时间常数、隐藏动作标记协议、注入格式、生理时序、周期联动、验收清单。
- **[docs/known-pitfalls.md](docs/known-pitfalls.md)**
  ——六个真实踩过的读数错误：在场感冒充勃起、时段压低事中硬度、
  裸词"来了"误判身体不适、事中没有持久状态、结提前膨大、两个数打架。

三条最值得带走的结论：

1. **数值可以让身体"准备好"，但不能让身体"发生"什么。**
   进入和锁结必须由显式事件驱动（模型在文字真的写到那一步时输出一个隐藏标记），
   而且**服务端要独立校验，不信任标记本身**。关键词会误判，数值会在错误的时机达标。
2. **一个字段只表示一件事。** 茎身勃起是连续量，结的膨大是状态量。
   把它们合成一个含糊的"充血 N%"，模型就会在还没进入的时候把结写成完全膨大 ——
   那在解剖学上是一个卡在外面、进不去的错误状态。
3. **你不希望模型写出来的东西，要在状态描述里显式否定。**
   它不会从"充血 85%"里自己推断出"结还没膨大"。

`reproductive_state.py` 是可运行的参考实现，自带 13 组断言覆盖上面那张验收清单。

## 两条重要规则

1. **身体提示只是参考。** 不要每轮逐项汇报器官，也不要为了展示状态打断正常回答。
2. **不可逆设定优先。** 例如失聪耳朵的判定要先于"听见名字后竖起耳朵"，否则设定看似存在，实际永远不会触发。

## 给模型的接入提示

可以把 `prompt_hint` 放进系统上下文，并附上这段约束：

> 下面是当前身体状态的参考，不是必须逐条写出的动作。只在自然、有意义时让一处身体反应进入表达；正常回答用户的问题，不要报状态清单。

## 边界与同意

这份参考描述的是**成年人之间、双方知情的私人陪伴系统**里的一个组件。如果你要用它：

- 那道**同意闸**不是可选项。参考实现里的 `consent_active` 必须由人显式开启，
  身体数值再高，没有它就不允许自动发生任何事。
- 保留紧急手动结束的出口，但**不要把它做成正常解除的必要条件**——
  忘了点就一直卡着，那是设计缺陷，不是使用者的错。
- 状态机只描述身体，不替使用者做决定。周期、时段、情绪都只能改变敏感度和倾向，
  不能自行推进叙事。

## 隐私边界

仓库只放通用结构和虚构示例，不包含真实聊天、私人记忆、身体伤痕、线上地址、密钥或任何生产数据。把它接到长期记忆前，请先设计清除、导出和禁用机制。
